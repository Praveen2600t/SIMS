# SICMS System Architecture & Engineering Guide

## 1. Overview
The **Smart Inventory Continuous Monitoring System (SICMS)** is an enterprise full-stack web application designed for continuous stock monitoring, daily stock movement analysis, perishable shelf-life tracking, and automated actionable alerts.

The system is a general-purpose, multi-sector inventory intelligence platform supporting diverse product domains—including Electronics, Pharmaceuticals, Industrial Raw Materials, FMCG, Food & Perishables, Automotive Spares, Lab Chemicals, Packaging Supplies, Hardware, and Office Equipment.

---

## 2. Technology Stack
* **Frontend**: Next.js 16 (App Router), React 19, TypeScript
* **Styling**: Tailwind CSS
* **Data Visualization**: Recharts
* **Backend API**: Next.js App Router Server Route Handlers
* **Database & ORM**: PostgreSQL via Prisma ORM 6

## 3. Database Design & Consistency
The database utilizes a fully normalized relational schema:
* `users`: Authentication records, RBAC roles (`ADMIN`, `STAFF`), and status.
* `categories`: 10 industrial and commercial categories.
* `locations`: Warehouse storage facilities, cold rooms, hazmat bays, and logistics staging hubs.
* `suppliers`: Industrial and commercial vendors with ratings and contact details.
* `products`: Master product catalog with SKU codes, categories, prices, units, and configurable alert thresholds (`minStockLevel`, `reorderQuantity`, `storageLocation`).
* `inventory_batches`: Per-batch shelf life and expiry tracking (`expiryDate`, `batchNumber`, `quantity`, `status`). Expiry is optional for non-perishable goods.
* `stock_movements`: Immutable transaction journal recording all stock changes (`IN`, `OUT`, `ADJUSTMENT`, `SALE`, `DAMAGE`, `RETURN`, `AUDIT`).
* `sales` & `sale_items`: Outbound dispatch records, customer/entity issues, and order details.
* `purchase_orders` & `purchase_order_items`: Inbound replenishment procurement orders and delivery receiving.
* `alerts`: Operational alerts generated by the Continuous Monitoring Engine with `recommendedAction`.
* `audit_logs`: User-attribution tracking for all sensitive and state-changing actions.
* `system_settings`: Key-value configuration store for dynamically adjustable monitoring rules.

### Consistency Guarantees
1. **Zero / Negative Stock Prevention**: In `InventoryService.processStockOut`, the server transaction reads current product balance and strictly rejects transactions if `requested_quantity > available_quantity`.
2. **Atomic Dispatches**: In `POST /api/sales`, the dispatch record and individual stock movements are committed in sequence, deducting inventory in the same transaction block.
3. **Audit Trail**: Every mutation records previous quantity, new quantity, movement type, reason, and authenticated user ID.

## 4. Continuous Monitoring Engine Architecture
The monitoring engine (`MonitoringService`) runs autonomously on stock mutations or via scheduled triggers (`/api/monitoring/run`):

1. **OUT_OF_STOCK**: Triggered when `currentQuantity <= 0`. Recommends immediate replenishment PO.
2. **LOW_STOCK**: Triggered when `0 < currentQuantity <= minStockLevel`. Recommends reorder requisition.
3. **EXPIRY_WARNING**: Evaluates active batches expiring within the configured window (`expiryWarningDays`, default: 14 days). Recommends priority dispatch or FEFO reallocation.
4. **EXPIRED**: Flags batches where `expiryDate < now()`, marks batch status as `EXPIRED`, and issues critical alert recommending quarantine and disposal.
5. **ANOMALY_REVIEW**:
   * Sudden quantity deductions exceeding `anomalyDropPercentage` (default: 35%) of stock in a single movement without a dispatch order reference.
   * Rapid manual adjustments (≥ `rapidAdjustmentLimit`, default: 3) in recent history.
6. **Auto-Resolution**: When stock is replenished above thresholds, existing open alerts are updated to `RESOLVED` with an explanatory note.
7. **Configurable Thresholds**: Authorized users can update rules via `PUT /api/monitoring/settings`.

## 5. Daily Stock Analysis Logic
The `AnalyticsService.getDailyStockAnalysis` provides daily tracking:
* **Opening Stock**: Balance at the beginning of the day (or prior day's closing balance).
* **Stock Received Today**: Sum of all `IN` and `RETURN` movements today.
* **Stock Issued / Sold Today**: Sum of all `OUT`, `SALE`, and dispatch movements today.
* **Current Balance / Closing Stock**: Active real-time available stock.
* **Net Daily Change**: Receipts minus dispatches and adjustments.

## 6. Security & Authorization
* Server-side authentication enforced via `requireUser` and `requireAdmin` in `src/lib/auth.ts`.
* Non-admin users are restricted from archiving products or manipulating system settings.
* Passwords hashed using bcrypt with salt rounds of 10.
* Session tokens stored in HTTP-only, SameSite lax cookies.
